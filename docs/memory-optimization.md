# 语音输入 0.6.0：持续内存优化报告

日期：2026 年 11 月 16–17 日。0.6.0 汇总此前内部 1.0.0／1.0.1 的优化。本报告性能测量的对照起点为本机内部 1.0.0，以下百分比只比较已测内部 1.0.1 载荷与该基线；重编号不改写历史构建 SHA 和数字。历史 Python、小模型、Rust 重构的不同样本数字保留在 [优化历史](optimization-history.md)。

环境：Windows x64、Intel Core i9-14900HX（24 核／32 线程）、RTX 5060 Laptop，系统可见物理内存 15.73 GiB。实时听写、热词、文件转录三功能及托盘操作方式保留。

性能测量 EXE（内部 1.0.1）：`9bace8c03644c0976556c6524fb03dec4addf37ec4af1c6688e3fdf3d937772c`；基线：`89e00ab101df68d9a78831bdac74c56551109bc5315d07c947ca6005482f2572`；两端原生 DLL：`8378440b27a7a1074261037a6ba33865aee59ef77f0b66c9a00458c82a14073a`。

0.6.0 重编号构建 SHA：`ebd6ee3cca2f18c21faf9f0650b6d6adf7030778f8acc13cbf3f1ae5868c4a1a`。识别代码、模型及推理配置不变；两个型号的 14 条完整请求和 52.6 秒实际文件 TXT／JSON／SRT 对已测构建全部精确一致。以下性能百分比继续使用原多轮对照数据，不从版本重编号的单轮检查重新推算。[发布说明](releases/0.6.0.md)

最终路线为原始张量字节等值的 external ONNX、动态 ASR 上下文及对齐器独立空闲释放修复。CPU 对齐器继续使用原有 repack，ASR CPU8/1、Vulkan 解码器、1.7B 默认模型、512 生成步预算保持。基线与候选分别使用 original-models/external-models 封存树，模型身份清单 SHA 为 `b044ce826a7780eefa82a8192600286492607c3edc2cbfdf87ff6c098bcf9169`。

进程冷首短各 5 轮；混合 7 请求与真实 CLI 文件转录各 3 轮，按顺序交替。保留 Windows 文件/驱动缓存；这里的冷启动指新进程加载首条请求。20ms 目标采样记录进程树私有提交和工作集；单 worker 的 OS PeakWorkingSet 是内核历史高水位，独立列出。进程树工作集相加可包含共享页重复计数，私有提交和物理驻留采用独立指标。

## 缺损配套文件错误路径

主代理在同一最终9BACE8C0…载荷上测试缺FE、仅缺BE（FE完整）、BE为空、BE为目录四项。四项均在ORT/原生加载前返回中文错误，文件CLI约0.069–0.079秒以exit1退出，serve文件回复约0.006–0.007秒，Job均清理。原90秒等待的根因是WorkerService对文件Segment加载错误无限退避重试；修正为文件立即失败，实时听写保留PCM重试逻辑。证据acceptance/negative3b-result.json。

## 未采用路线与完整记录

CPU noRepack 初筛节省约 204 MiB，但真实 CLI 稳定产生 1 个 80ms 时间戳差异，单变量 repack1/0 归因后已拒绝。ORT 1.32 也因单项 80ms 时间戳差异拒绝；All99/layout3 路线存在稳态提交或 WS 回退；固定对齐器线程仅节省不足 34 MiB 且延迟增加；Vulkan host-visible 开关没有结构内存收益。原始不利结果全部保留，未放宽时间戳门槛。

本报告全部百分比来自上述最终载荷匹配轮次，未混用初筛、失败 EC8F 候选或更早版本的测量。原始数据 summary.json、statistics.json、payload.json；逐轮导出、日志、采样与阶段记录在上一级 runs/。


## 改动、计量与采用边界

1. 三套模型的六个 ONNX 改为外置数据，保留原文件名并附带同前缀 `.weights.bin`。共 1632 个 tensor 的 dtype、维度与 payload SHA 逐项相同；节点、属性及其余 protobuf 内容保持。三个 GGUF 未改。整套模型从 3,375,904,052 变为 3,376,514,826 字节，仅增加约 596 KiB 对齐与索引开销。格式依据 [ONNX 外置数据规范](https://onnx.ai/onnx/repo-docs/ExternalData.html)。准备和逐项校验工具在 `tools/models/prepare_external_weights.py`，日常使用不运行 Python。
2. ASR 按输入长度分配上下文，保留原 512 步生成预算与最大容量，先释放旧上下文再创建新上下文。短输入通常使用 768、长样例使用 1280 容量，不缩短语音、不改变权重量化。
3. 每次请求前也检查对齐器的独立闲置期限，修复持续听写／Warmup 让已闲置对齐器一直保留的问题。原 10 秒／120 秒期限保留。
4. 加载线程启动前检查非空模型文件及配套权重。文件任务遇到加载失败立即返回中文错误；实时听写继续保留 PCM 并退避重试。缺前端、仅缺后端、空后端、后端路径为目录四项均在约 0.07 秒结束，未启动 ORT／原生模型加载，也未生成转录文件。

活动混合组统一暂时关闭闲置卸载，衡量两模型保留时的峰值和末段；正常 10 秒／120 秒生命周期另测。生命周期表来自服务测试的父子进程，托盘宿主另有实际路径检查。

私有提交反映进程承担的提交量；工作集反映当时驻留页。外置数据减少私有堆副本，并不会让工作集按同一幅度下降。本轮稳态工作集基本相当，完整转录与冷首句阶段的内核工作集峰下降；两类收益分别报告。采样峰值、内核历史高水位和整机可用内存分别记录，不相加为“总内存”。

## 功能、无障碍与交付校验

最终同一 EXE 已通过 83 项 Rust 测试（5 项专用硬件／协调探针未启用）；Python 开发工具 121 项中 120 通过、1 项因文件符号链接创建权限跳过，目录联接拒绝测试实际通过。298 项实际热词修正通过，包括 CapsWriter、Godot 识别变体及英文上下文保护。

最终 EXE 的正常托盘转录和缺配套权重的错误路径，均使用原生 MSAA／UI Automation 查找菜单、操作文件对话框、读回完成／中文错误状态并从“退出”结束。没有使用坐标或截图识字。DPI 144、感知级别 2；文件缺件语义状态约 0.2 秒可读。保持托盘界面和 AI schema 1，不新增主窗口或设置窗口。

识别质量结论来自固定公开音频、完整浮点编码与文件导出的回归；本轮没有另行进行人工标注 WER 评测。新版本继续默认 1.7B，0.6B 可选。

## 收敛与回退

可直接落地的路线已收敛。关闭 CPU repack 虽省约 205 MiB，但改变一个 80 ms 时间戳，已经撤回；新 ORT 同样未通过严格时间戳门槛。离线 All99 模型虽降低私有提交峰，却增加约 552 MiB 常驻工作集和约 1.8 GB 存储，未采用；离线缓存还需要匹配执行提供方和硬件，[ORT 官方说明](https://onnxruntime.ai/docs/performance/model-optimizations/graph-optimizations.html#onlineoffline-mode)列出了相关要求。

正式文件输入已有流式处理、固定分段和有界队列，剩余拷贝只有几 MiB。独立拆分编码器会改变全局注意力上下文；缩小 Vulkan 微批的主机缓冲潜力不足约 12 MiB，且增加分派；ORT 优先执行次序缺少当前 C API／Rust 的现成入口，需另维护原生运行库。上述后续成本相对本轮收益较高，停止继续扩展。

上述性能研究阶段先完成本机部署，随后按用户要求以 0.6.0 发布源码和版本标签。研究阶段的事务备份位于正式安装目录旁 `memory-goal-backup-20261117`，保留原 EXE、原 ONNX、原设置及文档。退出语音输入后，备份中的 `rollback_encoder.py` 默认只校验，明确加 `--execute` 执行回退。多轮回退按部署顺序逆向执行；如用户后来编辑目标文件，回退工具会保留该变化并停止覆盖。

原始测量、未采用方案、负向用例、UI 语义结果、全部哈希及部署收据保存在本机 `evidence/memory-goal-20261116/`；个人热词、录音、模型和本机证据不作为公开源码载荷。
