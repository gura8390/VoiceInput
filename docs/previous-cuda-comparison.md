# 先行版与 GitHub 旧 CUDA 技术分支对比

日期：2026 年 11 月 17 日。设备、采样与正式安装状态见 [三版报告](ggml-three-versions-comparison.md)。本页补充用户要求的旧技术分支对照，全部重新在本机执行，没有拿旧的 39 请求耗时直接与新的五请求相除。

## 结论

同为 1.7B、同用 CUDA 解码时，将 CPU ORT 编码替换成先行版的 GGML / CUDA 编码，五请求耗时减少 **37.53%**、累计 CPU 时间减少 **27.48%**，峰私有提交增加 **743.34 MiB（23.35%）**，专用显存峰增加 **734.02 MiB（47.68%）**。ASR 编解码核心同时使用 GPU 有明确的速度收益，资源成本也明确增加；Mel 等图外工作继续在 CPU。

与 GitHub 原 0.6B 技术分支整体比较，先行版的模型更大，五请求仍快 **17.12%**，但峰私有提交由 **1903.07 → 3925.07 MiB**，增加 **106.25%**；专用显存由 **747.48 → 2273.51 MiB**。旧分支私有提交和显存更低，先行版在当前小型参考集合中识别错误更少。这是跨版本、跨模型的整体取舍。

本次继续保留正式 0.6.0 基准版，没有切换安装或自启动。先行版是性能候选，未在所有内存指标上胜出。

## 核实了哪个分支

现场查询 GitHub 和远端 Git 引用，确认 [0.4.3—CUDA](https://github.com/gura8390/YuYbUuRu/tree/0.4.3%E2%80%94CUDA) 固定为 [3b7c123df6fe8cb8e0c220f65258652297419fa5](https://github.com/gura8390/YuYbUuRu/commit/3b7c123df6fe8cb8e0c220f65258652297419fa5)，内部版本 `0.4.3-cuda.1`。它固定使用 0.6B，尚无选择 1.7B 的配置和命令参数。

因此做了两项独立对照：

| 对照 | 旧侧 | 新侧 | 能说明的差异 |
| --- | --- | --- | --- |
| A：GitHub 原分支 | 原源码重建、原 0.6B INT4 编码 / Q4_K 解码、CPU ORT＋CUDA | 当前先行 1.7B、GGML / CUDA＋CUDA | 整个版本和模型组合的实际成本、速度和固定样本输出 |
| B：相同 1.7B | 当前 EXE 的 CPU ORT＋CUDA，标为“旧 CUDA 路线复现，非原分支” | 同 EXE 的 GGML / CUDA＋CUDA | 相同模型、量化、原生库和应用代码下，改变编码后端的收益 |

A 没有把 1.7B 支持移植进旧代码。原源码用 Rust 1.95 及 `--locked` 重建，源码工作树干净；66 项测试通过、5 项原有硬件 / 模型测试忽略，零失败。原编码 / 对齐内嵌 ONNX、原 Q4 GGUF、ORT 1.24 及历史单输出 / CUDA 延迟 cuBLAS 原生组件均从归档找回。原生目录按当时选中的组件重组，使用当前热词；这是原源码重建，EXE 与历史原二进制哈希不同，不称为原安装包整包恢复。

B 两侧均为最终 `2c1302bd…` 程序，逐文件核对运行库和选定模型相同。保存配置只有 `encoder_provider` 不同，实际运行时各自的隔离 `app_dir` 不同。没有把 B 冒称为原 GitHub 分支的原样结果。

## A：原分支 0.6B 与先行 1.7B

每侧独立 prime 排除，三对新进程按 AB / BA / AB 顺序串行执行；每轮五请求、相同四段 PCM，包含精确 60 秒文件模式。下表是三轮中位数。

| 指标 | 原分支 0.6B | 先行 1.7B |
| --- | ---: | ---: |
| 模型 ready，秒 | 0.575 | 0.963 |
| ready＋首条完整请求，秒 | 0.740 | 1.069 |
| 五请求完整时间合计，秒 | 5.217 | 4.323 |
| ASR 编码累计，秒 | 1.3407 | 0.1661 |
| 60 秒文件模式完整请求，秒 | 4.680 | 4.026 |
| Job 最终累计 CPU，CPU 秒 | 75.375 | 71.656 |
| 峰私有提交，MiB | 1903.07 | 3925.07 |
| 峰总工作集，MiB | 1180.25 | 1671.72 |
| 峰私有工作集，MiB | 896.84 | 800.91 |
| 末段私有提交，MiB | 1692.38 | 3604.81 |
| 末段总工作集，MiB | 970.31 | 896.33 |
| 末段私有工作集，MiB | 686.85 | 591.56 |
| 独显 dedicated 采样峰，MiB | 747.48 | 2273.51 |

先行五请求快 17.12%，60 秒文件模式快 13.96%，累计 CPU 少 4.93%；模型 ready 慢 67.42%，ready＋首句慢 44.40%。峰总工作集增加 41.64%，末段私有提交增加 113.00%，显存峰增加 204.16%。峰私有工作集和末段总工作集则下降，分别保留这些计数，不统一称为“内存减少”。

五请求时间范围：旧分支 4.843–5.293 秒，先行 4.196–4.457 秒。峰私有提交范围：旧分支 1901.79–1904.82 MiB，先行 3924.36–3925.59 MiB。两侧各 15 次正式请求与自身 prime 和同版跨轮精确，跨模型共有 6 / 15 条请求的结果或原始字段不同。

两侧各自 15 / 15 条正式请求精确复现；跨侧 12 / 15 条精确，其余是每轮同一条 60 秒文件，涉及真实字词、token 和时间戳。CPU 编码和 GPU 编码的浮点运算路径不同，没有要求两侧中间值逐位相同。

## 扩展参考质量与输出差异

使用与主三版相同的八段材料、三个原生种子，每侧 24 次请求。七段有公开参考文本，一段 60 秒没有完整逐字稿；材料含重复和拼接，统计不是独立大规模语料的识别率。

| 路线 | 有参考请求 | 编辑数 / 参考字符 | CER |
| --- | ---: | ---: | ---: |
| GitHub 原分支 0.6B | 21 | 83 / 936 | 8.86752% |
| 同 1.7B CPU ORT＋CUDA | 21 | 31 / 936 | 3.31197% |
| 先行 1.7B GGML / CUDA | 21 | 31 / 936 | 3.31197% |

同模型两侧的七个有参考输入，三个种子的 CER 均没有增减；旧 0.6B 多 52 次字符编辑是跨版本、跨模型整体结果，不归因于 GGML 编码后端，也不外推为所有录音的准确率增幅。

同模型 60 秒文件的 seed 42 存在三处“再 / 现在”真实字词变化；没有完整真值，不判定哪侧更准确。CPU 侧 224、先行 227 个归一化正文 token 中，221 个能按相同文本匹配；220 个起点相同，末尾“的”的起点从 51.12 变为 51.04 秒。seed 314159 全部文本、token、时间戳相同；seed 20261117 仅标点 / 大小写变化，224 个正文 token 的时间戳相同。主三版集合和实际 CLI 的差异仍以 [主报告](ggml-three-versions-comparison.md) 各自口径为准。
