# 加载内存优化说明

本文记录内部 1.0.0 的有界上传优化。对外 0.6.0 汇总后续内部 1.0.1 的权重外置、ASR 动态上下文和忙队列闲置释放；最新测量见 [持续内存优化报告](memory-optimization.md)。下列数字仍对应各自原始对照与构建身份。

2026 年 11 月 16 日，语音输入 1.0.0 本地优化版保持实时听写、热词和文件转录三个功能，默认模型仍为 1.7B，0.6B 可选。

## 采用的改动

Windows Vulkan 加载 GPU 权重时，使用原生库已有的 4×1 MiB 缓冲环分块读取、异步上传。CPU 权重继续只读映射。编码器与解码器仍并行初始化；编码器预热、模型精度、CPU 对齐器、120 秒 ASR 卸载及 10 秒对齐器卸载策略保持。

后端能力和上传器初始化条件满足才启用，条件不满足时继续原映射路径；上传开始后的驱动故障处理沿用原逻辑。

## 本机对照结果

比较对象是本次优化前后的两个 1.0.0 构建。固定 1.7B、CPU 8/1 线程、Vulkan 和公开音频。每版五轮进程冷加载、三轮混合识别与文件对齐、三轮完整文件转录，交错运行。保留 Windows 和驱动缓存。下表为中位数。

| 指标 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 加载时单 worker 的内核工作集历史峰 | 2434.33 MiB | 2074.17 MiB | 减少 360.16 MiB，14.80% |
| 模型初始化请求 | 1.516 秒 | 1.343 秒 | 减少约 11.42% |
| 真实首条识别，含加载 | 1.930 秒 | 1.944 秒 | 增加约 0.71% |
| 三条热态短句累计 | 0.842 秒 | 0.842 秒 | 增加约 0.09% |
| 完整 52.60 秒文件转录 | 7.294 秒 | 7.364 秒 | 增加约 0.95% |

加载后私有提交增加约 7.30 MiB，工作集仍约 22 MiB。混合请求的峰值私有提交减少约 235.34 MiB（6.14%）。完整 CLI 的采样工作集峰中位数反而增加约 14.38%，累计 CPU 指标也有增加，不能宣称所有阶段的内存或 CPU 均下降。

## 识别与限制

36 条正式请求的文本、token、时间戳及原生结果一致；六次完整转录的 18 个导出文件哈希一致。0.6B 另做公开短音频检查，三种导出逐字节一致。这用于检验本轮实现变化，不等于普遍识别率评测。

加载峰值仍会波动，本轮旧版范围 2309.68–3616.03 MiB，新版范围 1926.44–2593.94 MiB。这是观测值，不能作为固定内存上限。进程工作集降低不等于整机物理 RAM 同比例释放，私有提交与工作集也不能相加。

目录整理前的版本同样出现过高峰；此前新旧中位差异的全部原因没有确定。本次针对的是已经定位到的加载驻留机制，不将历史差异简单归因于目录变化。

完整逐轮测量、采样、载荷哈希和未采用方案保存在本机源码的 `evidence/transient-ws-20261116/`。历次路线见 [优化记录](optimization-history.md)。本轮只在本机部署，未推送 GitHub。
