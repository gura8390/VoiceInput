# OpenCode Hex v3.4.0 与 YuYbUuRu v0.6.0 本机性能对比测试

- **测试日期**：2026 年 11 月 24 日
- **对照对象**：
  - [OpenCode Hex v3.4.0](https://github.com/anomalyco/hex/releases/tag/v3.4.0)（Windows x64 官方发布版，默认推荐中文模型 `qwen3_asr06_b` / `Qwen3-ASR-0.6B-Q8_0.gguf`）
  - 语音输入 · YuYbUuRu v0.6.0（`0.6b` 同规模对照与默认 `1.7b` 配置）
- **测试平台**：Windows 11 x64，Intel Core i9-14900HX（24 核 32 线程），15.7 GB 内存，NVIDIA GeForce RTX 5060 Laptop GPU（8 GB 显存）。

## 环境、架构与采样方法

### 架构与模型差异

| 维度 | OpenCode Hex v3.4.0 | YuYbUuRu v0.6.0（0.6B） | YuYbUuRu v0.6.0（1.7B 默认） |
| --- | --- | --- | --- |
| 入口与程序体积 | `hex.exe`（83.2 MiB，集成 Rune UI、QuickJS 与 transcribe.cpp） | `语音输入.exe`（6.5 MiB，原生 Win32 托盘 + 按需 worker） | 同左 |
| 模型与量化 | `Qwen3-ASR-0.6B-Q8_0.gguf`（811 MiB，单文件） | INT4 ONNX 编码器（外置权重）+ Q4_K GGUF 解码器（约 570 MiB） | FP16 ONNX 编码器（外置权重）+ Q5_K_M GGUF 解码器（约 2.0 GiB） |
| 编码器后端 | **Vulkan GPU**（RTX 5060，transcribe.cpp / ggml） | **CPU 8 线程**（ONNX Runtime，固定形状前端 Arena） | **CPU 8 线程**（ONNX Runtime，固定形状前端 Arena） |
| 解码器后端 | **Vulkan GPU**（RTX 5060） | **Vulkan GPU**（RTX 5060，llama.cpp，单输出预留 + 动态上下文） | **Vulkan GPU**（RTX 5060，llama.cpp，单输出预留 + 动态上下文） |
| 进程与空闲卸载 | 单进程；`labs.unload_idle` 默认关闭（模型长期常驻）；卸载后仍保留 Rune GUI 外壳 | 托盘宿主与推理 worker 分离；默认 120 秒空闲退出整个推理进程，内存与显存归回宿主态 | 同左 |

### 采样口径与测试语料

- **主机内存与 CPU**：通过 Win32 Job Object（`CreateJobObjectW`）托管完整进程树，调用 `GetProcessMemoryInfo` 与 `GetProcessTimes` 以 20 ms 间隔采样私有提交（Private Commit）、私有工作集（Private Working Set）、总工作集（Working Set）、单进程内核峰值工作集（OS Peak WS）与累计 CPU 时间；峰值 CPU 核数按 200 ms 滑动窗口计算。
- **GPU 显存**：通过 WDDM PDH（`\GPU Process Memory(*)\Dedicated Usage` / `Shared Usage`）以 100 ms 间隔按所属 PID 采样进程级专用显存与共享显存。
- **缓存与轮次**：所有冷/热测试前均执行一轮丢弃的预热，使两侧同样处于 OS 文件缓存与 GPU Vulkan 着色器/管线缓存已预热状态；随后三轮交错执行，取中位数报告。Hex 在隔离配置目录下运行，关闭自动更新，与本机环境完全隔离。
- **测试语料**：统一为 16 kHz 单声道 PCM16 公开语料（来源同 [FireRedASR2-AED 对比记录](history/fireredasr2-aed.md)）：
  - 6 段短/中语料：`hello_zh`（2.320 s）、`hello_en`（2.240 s）、`aishell_zh`（4.204 s）、`conversation_zh`（1.800 s）、`song_cmd_zh`（1.992 s）、`meeting_zh`（12.369 s）
  - 1 段长中英混合语料：`long_mixed`（52.600 s）
  - 7 段合计 **77.525 秒**音频。

## 一、后台静置与常驻开销（10 秒稳态）

| 状态 | 私有提交 (MiB) | 私有工作集 (MiB) | 总工作集 (MiB) | 专用显存 (MiB) | 共享显存 (MiB) | 静置 CPU 核数 / 整机占比 |

- 后台闲置超过 120 秒后，YuYbUuRu 退出推理子进程，回落至 **6.6 MiB 私有提交 / 22.4 MiB 工作集 / 0 MiB 显存**；Hex 默认长驻 **1,406.3 MiB 私有提交 / 248.5 MiB 工作集 / 1,129.6 MiB 显存**。
- 同为 0.6B 模型加载后静置时，YuYbUuRu 0.6B 私有提交比 Hex 低 **50.6%**，专用显存低 **65.8%**，且加载后裁剪工作集至 **13.0 MiB**。

## 五、样本转写观察与综合结论

1. **内存与显存占用：YuYbUuRu 全面占优**
   - 同规模 0.6B 热态下，YuYbUuRu 峰值私有提交低 **54.0%**（1,043.3 vs 2,270.1 MiB），专用显存低 **61.1%**（557.4 vs 1,433.2 MiB），单进程 OS 峰工作集低 **35.7%**（674.5 vs 1,048.2 MiB）。
   - 日常后台闲置差距最显著：YuYbUuRu 120 秒空闲退出推理进程，降至 **6.6 MiB 私有提交 / 0 MiB 显存**；Hex 默认保持 **1,406.3 MiB 私有提交 / 1,129.6 MiB 显存** 常驻。
   - 即使使用 YuYbUuRu **1.7B** 默认大模型，其专用显存峰值（1,404.5 MiB）仍略低于 Hex 0.6B 单实例（1,433.2 MiB）。
2. **CPU 占用：Hex 全面占优**
   - Hex 将音频编码与解码全链路置于 Vulkan GPU，热态 7 段队列仅消耗 **0.88 CPU 秒**（峰值 **0.78 核 / 2.43%**），仅为 YuYbUuRu 0.6B（8.58 CPU 秒，峰值 7.39 核）的约 **1/10**、1.7B（20.66 CPU 秒，峰值 7.64 核）的约 **1/23**。
3. **转写延迟与输出观察**
   - **短句冷启动与日常短句听写（1.8–12.4 s）**：YuYbUuRu 0.6B 更快（冷启动 0.824–0.846 s 胜过 Hex 的 1.319–1.365 s；热态 6 段合计 0.905 s 胜过 Hex 单实例 1.151 s）。
   - **长音频热态纯转写（52.6 s）**：Hex 0.6B 更快（0.968 s / RTF 0.0184 胜过 YuYbUuRu 0.6B 的 1.382 s / RTF 0.0263 与 1.7B 的 2.703 s / RTF 0.0514）。
   - **样本文本观察**：5 段短句三者输出逐字一致；52.6 秒中英混合长音频中，YuYbUuRu 1.7B 完整保留全部两处英文片段且中文口语细节最准确；同为 0.6B 时，Hex（Q8_0）保留了全部两处英文片段，YuYbUuRu 0.6B（INT4/Q4_K）漏出一处英文片段。
